---

## 1. Threat Model Scope & Trust Boundaries
1. **Trust Boundary 1 (Flutter Client <-> Backend API):** Untrusted public internet; client device/binary can be inspected or tampered with.
2. **Trust Boundary 2 (Backend <-> Public Web URLs):** Backend initiates outbound HTTP requests to untrusted user-supplied URLs.
3. **Trust Boundary 3 (Backend <-> AI Provider & Untrusted Text):** User-submitted PDF/URL text and external YouTube text enter LLM prompts; LLM output re-enters backend persistence/queries.
4. **Trust Boundary 4 (Backend <-> PostgreSQL & Secrets):** Holds user PII, credentials, and third-party API keys.

## 2. STRIDE Threat Register

| ID | Category / Domain | STRIDE | Threat Description | Impact | Likelihood | Proposed Mitigation | Verification Approach |
|---|---|---|---|---|---|---|---|
| **THR-001** | Authentication | **Spoofing** | Brute-force login, credential stuffing, or forged/expired JWT tokens granting unauthorized account access. | High | Medium–High | ASP.NET Core Identity adaptive password hashing (`SEC-002`); strict JWT signature/expiry/issuer validation (`SEC-001`); per-IP/account rate limiting (`SEC-011`, `TBD-021`); short-lived JWT + revocable refresh rotation (`DEC-P10`). | Negative auth API tests (tampered/expired/alg=none JWT), rate-limit `429` tests in S2/S11. |
| **THR-002** | Authorization & User Isolation | **Information Disclosure / Tampering** | IDOR: authenticated user guesses/substitutes another user's `SourceId` to view, retry, or delete another learner's sources or feeds. | High | High (if unchecked) | Mandatory server-side `OwnerUserId == JwtSub` check on every command/query (`SEC-003`, `BR-006`); opaque GUID IDs. | Automated cross-user IDOR integration test suite across every user-scoped endpoint. |
| **THR-003** | SSRF (Web URL Fetch) | **Elevation / Info Disclosure** | Attacker submits `http://127.0.0.1`, `169.254.169.254`, `10.0.0.0/8`, IPv6 ULA, or uses DNS rebinding / HTTP 302 redirects to probe internal services or cloud metadata. | **Critical** | High | Scheme allowlist (`http`/`https`); pre-connect DNS resolution + IP blocklist (loopback, RFC1918, link-local, metadata, multicast, IPv6 equivalents); connect to resolved IP directly; re-validate on every redirect hop; disable proxy/default credentials; strict timeouts & size caps (`SEC-006`). | Unit & integration SSRF test suite covering IPv4/IPv6 bypass encodings, DNS rebinding mocks, and redirect chains to internal IPs (S4/S11). |
| **THR-004** | Malicious / Malformed URLs & Payloads | **Denial of Service / Tampering** | Slowloris, zip/gzip bombs, infinite streams, or binary files served from submitted URLs exhausting backend memory/threads. | High | Medium | Stream-read with hard byte cap (`TBD-005`), strict connect/total request timeouts (`NFR-003`), `Content-Type` allowlist (`text/html`, `text/plain`), HTML parser depth/size limits. | Mock HTTP server tests sending oversized chunked streams, slow responses, and non-HTML binaries (S4). |
| **THR-005** | PDF Input Validation | **Denial of Service / Tampering** | Oversized or maliciously crafted PDF text payloads sent directly to API, or corrupt PDF crashing Flutter local extractor. | Medium–High | Medium | Client-side file size cap & isolated extraction (`WF-03`, `TBD-005`); server-side request body limit, UTF-8 validation, and character cap (`SEC-007`). | Client malformed-PDF test fixtures + API oversized/invalid-encoding negative tests (S4/S10). |
| **THR-006** | Resource Exhaustion & Rate Limiting | **Denial of Service** | Flood of source submissions triggers expensive LLM inference and exhausts daily YouTube Data API quota for all users. | High | Medium–High | Per-user/IP rate limits (`SEC-011`, `TBD-021`), per-source query caps (`TBD-014`), bounded async queue concurrency, and YouTube quota circuit-breaker/handling. | Load/rate-limit integration tests verifying `429` enforcement and queue stability (S8/S11). |
| **THR-007** | Secrets Management | **Information Disclosure** | YouTube API key, JWT signing key, DB password, or LLM API key leaked via Flutter binary, Git commit, or error responses. | **Critical** | Medium | Never place backend secrets in Flutter (`BR-008`, `SEC-008`); use env vars/secret manager; CI secret scanning; scrub `appsettings.json` placeholders (`CONF-003`). | Static secret scanner in CI + decompile/string-search inspection of Flutter release artifact (S3/S11). |
| **THR-008** | Client Token Storage | **Information Disclosure** | JWT/refresh tokens stored in plaintext `SharedPreferences` extracted from rooted/compromised device backups. | High | Medium | Use OS-encrypted Keychain/Keystore secure storage (`SEC-005`); clear on sign-out (`FR-004`). | Flutter code audit & storage verification (S3/S11). |
| **THR-009** | AI Prompt Injection | **Tampering / Repudiation** | Malicious text inside a PDF or scraped webpage instructs LLM to ignore task, output deceptive queries, or inject markup/scripts. | Medium–High | Medium | Delimit untrusted text from system instructions (`SEC-009`); zero LLM tool/DB/network privileges; strict schema + character/content sanitization on output (`SEC-010`). | Adversarial prompt-injection test suite in `evaluation-strategy.md` (S5/S11). |
| **THR-010** | Untrusted AI Output | **Tampering / DoS** | Malformed JSON, huge arrays, or XSS/script strings returned by LLM crash downstream parsers or pollute YouTube queries/UI. | Medium | Medium | Treat AI output as untrusted (`BR-005`, `SEC-010`): strict schema validator, array/length caps, plaintext-only escaping in UI. | Unit tests with malformed JSON, extreme lengths, and HTML/script payloads (S5). |
| **THR-011** | Logging of Sensitive Content | **Information Disclosure** | Full source text, PII, JWTs, or API keys written to application logs or crash dumps. | Medium–High | Medium | Structured logging redaction policy (`SEC-012`); log `SourceId`, `UserId` (or pseudonymous hash), `CorrelationId`, and status codes only—never tokens, passwords, or raw text bodies. | Log sink audit across error/failure scenarios in S8/S11. |
| **THR-012** | External API Abuse (YouTube) | **Denial of Service / Legal** | Violating YouTube API Terms of Service (downloading videos, hiding branding, playing non-embeddable videos, stale unrefreshed metadata). | High | Medium | Metadata-only storage (`BR-001`), compliant IFrame embed player (`ADR-006`, `BR-002`), `embeddable=true` filtering (`WF-09`), ToS-compliant cache TTL (`TBD-015`). | Pre-launch compliance checklist review against YouTube API Services ToS in S6/S11. |
| **THR-013** | Data Deletion & Retention | **Privacy / Compliance** | Orphaned source text, analyses, or viewing history retained indefinitely after user deletes a source or account. | Medium–High | Medium | Explicit cascade/purge workflows on source deletion (`FR-023`) and account deletion (`SEC-014`); define retention SLAs in `TBD-019` and external LLM disclosure in `TBD-020`. | Integration tests verifying zero residual user records after delete operations (S8/S11). |
